# SafeLoop 3분 사용자 인터뷰 가이드

> 상태: 인터뷰 진행 전  
> 목표: 1명당 2~3분, 5명 이상  
> 목적: 기존 운전점수의 행동 변화 효과와 운전 전후 누락만 빠르게 검증한다.

## 1. 인터뷰 대상

인터뷰 대상은 모두 **자가용으로 출퇴근하는 운전자**로 통일한다. 주간 출퇴근 일수와 블루링크, 기아 커넥트, 보험사 안전운전 특약 등 운전점수·주행 리포트 사용 경험은 선발 조건으로 제한하지 않고 질문에서 확인한다.

운전점수 사용 경험이 없는 참가자는 사용하지 않은 이유를 기록한다. 이 참가자의 H1 답변은 `?`로 판정하되, 운전 전후 습관에 관한 H2 답변은 그대로 활용한다.

## 2. 검증할 가설

| ID | 가설 | 통과 기준 |
|---|---|---|
| H1 | 점수를 확인해도 다음 운전에서 바꿀 행동을 알기 어렵다. | 5명 중 3명 이상 |
| H2 | 출발 전·도착 후 반복적으로 놓치는 행동이 있다. | 5명 중 3명 이상 |

이 기준은 팀 내부의 아이디어 검증 기준이며 통계적 대표성을 의미하지 않는다.

## 3. 3분 진행 순서

### 시작 안내 — 15초

> 운전 습관 앱 아이디어를 검토하고 있습니다. 이름이나 차량번호는 기록하지 않으며, 5분 이내로 실제 경험만 여쭤보겠습니다.

### 질문 — 약 2분

1. **일주일에 며칠 자가용으로 출퇴근하며, 운전점수 서비스를 사용해 본 적이 있나요?**  
   사용 경험이 있다면 서비스명을, 없다면 사용하지 않은 이유를 확인합니다.
2. **운전점수를 사용해 봤다면 최근 점수의 이유를 이해했고 실제로 바꾼 행동이 있었나요?**  
   사용 경험이 없다면 이 질문은 건너뜁니다.
3. **출발 전이나 도착 후에 반복해서 빠뜨리는 행동이 있나요?**  
   예: 안전벨트, 목적지 설정, 창문, 도어, 주차 상태

### 종료 — 10초

> 답변 감사합니다. 내용은 개인을 식별할 수 없게 요약하여 아이디어 검증에만 사용하겠습니다.

## 4. 진행 원칙

- 앱 기능을 먼저 길게 설명하지 않는다.
- “필요하지 않나요?” 같은 유도 질문을 피한다.
- 답변이 길어지면 “가장 최근 사례 하나만 말씀해 주세요”라고 정리한다.
- 이름, 차량번호, 상세 이동 경로는 기록하지 않는다.
- 녹음은 사전 동의를 받은 경우에만 한다.
- 각 사람에게서 핵심 답변과 인용문 한 문장만 남긴다.

## 5. 결과 판정

답변은 [INTERVIEW_RESPONSES.md](INTERVIEW_RESPONSES.md)에 기록한다.

- `O`: 가설을 지지하는 답변
- `X`: 가설을 반박하는 답변
- `?`: 판단할 근거가 부족한 답변

5명 중 3명 이상이 `O`이면 해당 가설을 통과로 본다.

- H1·H2 모두 통과: `전 주기 + 행동 변화 코칭` 방향 유지
- H1 기각: 점수 설명보다 행동을 지속시키는 동기와 탑승 시 브리핑에 집중
- H2 기각: 출발 전·도착 후 기능을 축소

## 6. 제품 화면 방향

이 항목은 인터뷰 질문이 아니라 현재 제품 설계 결정으로 관리한다.

- **탑승 시 브리핑:** 차량에 탑승하면 출발 전에 확인할 안전 상태와 이전 운전에서 이어갈 행동 하나만 짧게 안내한다.
- **별도 리포트:** 운전 종료 후 사용자가 원할 때 사건 근거, 점수, 미평가 사유, 기간별 추이를 자세히 확인한다.
- 주 1회 확인을 강제하지 않고, 브리핑은 매 탑승 시 제공하며 리포트는 정차 상태에서 별도로 열어 본다.
