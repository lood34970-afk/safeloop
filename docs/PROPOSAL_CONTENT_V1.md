# SafeLoop 공모전 제안서 내용 초안 v1

> 작업명: SafeLoop(세이프루프)
> 대상: 주 4일 이상 자가용으로 출퇴근하며 안전 행동을 꾸준히 유지하고 싶은 운전자
> 검증 상태: 기술 API 검증 완료 및 사용자 인터뷰 진행 중 초안

## 1. 앱 한 줄 소개

차량과 내비게이션 데이터로 출발 준비·주행·도착 정리 습관을 기록하고, 탑승 시 짧은 안전 브리핑과 운전 종료 후 별도 리포트를 제공하는 전 주기 운전 코치입니다.

## 2. 기획 배경

초기 인터뷰 5명은 기존 운전점수에 표시된 위반 사항을 통해 점수 이유를 이해할 수 있다고 답했습니다. 그러나 2명은 보험 할인 혜택이 있을 때만 행동을 바꿨고, 기존 점수는 안전벨트 착용·도어·타이어 상태 확인 같은 출발 준비와 창문·도어·주차 상태 확인 같은 도착 후 습관을 하나의 지속적인 개선 흐름으로 연결하지 못했습니다.

SafeLoop는 반복 빈도가 높은 출퇴근을 안전 습관 형성의 계기로 바꿉니다. 차량에 탑승하면 출발 전에 확인할 안전 상태와 이어서 실천할 행동 하나만 짧게 브리핑하고, 운전 종료 후에는 사건 근거와 점수, 평가에서 제외한 사건과 이유를 별도 리포트로 보여 줍니다. 크루즈 컨트롤·ADAS가 개입했거나 API 미지원·센서 신뢰도가 부족한 구간은 운전자에게 벌점을 주지 않고 미평가 처리합니다.

초기 타깃은 자가용으로 출퇴근하는 운전자입니다. 현재 5명 인터뷰에서 점수 이해 여부와 행동 변화 조건을 확인했으며, 출발 전·도착 후 반복 누락 사례를 추가 확인해 기능 우선순위를 확정합니다.

## 3. 앱 주요 기능 및 차량 특화 요소

### Safe Start — 출발 전

- Vehicle Seat API로 운전석 안전벨트를 확인하고, 열린 도어·트렁크, 타이어·안전 경고, 목적지 설정 여부를 출발 전에 확인합니다.
- 기어·차속으로 아직 정차 상태인지 확인해 운전 중 조작을 요구하지 않습니다.
- 차량 또는 권한이 제공하지 않는 항목은 `확인 불가`로 표시하고 점수에서 제외합니다.

### Safe Drive — 주행 중

- 차량 차속과 현재 도로 제한속도를 결합해 제한속도 준수 시간을 기록합니다.
- 방향지시등 신호와 내비게이션 회전·분기 이벤트를 결합하고, ADAS 차선 변경 이벤트를 사용할 수 있는 환경에서는 실제 차선 변경 전 방향지시등 사용을 평가합니다.
- 크루즈 컨트롤과 확인 가능한 ADAS 개입 구간은 자동운전 보조 구간으로 분리해 운전자 점수에서 제외합니다.
- 주행 중에는 긴 피드백이나 조작을 요구하지 않고 필요한 경우 짧은 상태만 보여 줍니다.

### Safe Close — 도착 후

- 정차·P단·주차브레이크를 확인한 뒤 열린 창문·도어·트렁크와 남은 차량 경고를 알려 줍니다.
- 운전 종료 후에만 사건별 근거와 미평가 이유를 자세히 보여 줍니다.

### Briefing & Report — 행동 변화

- 탑승 시 브리핑은 출발 안전 상태와 이전 운전에서 이어갈 행동 하나만 짧게 보여 줍니다.
- 별도 상세 리포트는 `무엇을·언제·어떤 데이터로 판단했는지`와 기간별 변화를 보여 줍니다.
- 주 1회 확인을 강제하지 않고, 매 탑승 시 브리핑과 정차 중 열어 보는 리포트의 역할을 분리합니다.
- 모든 데이터는 먼저 차량 내 로컬에서 처리하고, 사용자가 동의한 요약 지표만 향후 동기화 대상으로 검토합니다.

차량 특화성은 스마트폰 GPS만으로 알기 어려운 안전벨트·방향지시등·브레이크·도어·창문·ADAS 상태와 차량 내비게이션의 경로 이벤트를 하나의 시간축으로 결합하는 데 있습니다. 차량 데이터가 없으면 핵심 평가와 공정한 제외 판단이 성립하지 않습니다.

## 4. 주요 사용 시나리오

1. 주 5일 자가용으로 출근하는 운전자가 차량에 탑승합니다.
2. 탑승 시 브리핑이 운전석 안전벨트와 도어·타이어 상태, 이어서 실천할 행동 하나를 짧게 보여 줍니다. 센서 권한이 없는 항목은 확인 불가로 명시합니다.
3. 운전자는 정차 상태에서 목적지를 설정하고 출발합니다.
4. 앱은 주행 중 차속·제한속도, 방향지시등·회전/분기 또는 차선 변경, 크루즈·ADAS 상태를 시간축에 기록합니다. 운전자 조작을 요구하지 않습니다.
5. 크루즈나 ADAS가 개입한 구간과 신뢰도가 부족한 구간은 미평가 처리합니다.
6. 도착해 P단과 주차브레이크가 확인되면 Safe Close가 열린 창문·도어 등 놓친 항목만 알려 줍니다.
7. 운전 종료 후 사용자는 별도 리포트에서 단계별 사건 근거와 `다음 운전에는 차선 변경 2초 전 방향지시등 켜기` 같은 행동 하나를 확인합니다.
8. 다음 탑승 시 브리핑이 같은 행동을 짧게 상기시키고, 상세 변화는 리포트에서 확인합니다.

## 5. 개발 계획

Android Automotive OS 기반 Kotlin·Jetpack Compose 앱으로 구현합니다. Pleos Vehicle SDK 2.3.2의 Seat, Door, Tire, Safety, TurnSignal, DrivingMode, Brake, Window 도메인과 AAOS CarPropertyManager의 차속·기어·주차브레이크 속성을 사용합니다. NaviHelper 3.0.5는 경로 상태, TBT, 현재 도로 제한속도 이벤트에 사용합니다. AVD 기술 검증에서 안전벨트·운전석 도어·창문·브레이크·방향지시등·크루즈 capability와 현재 상태, AAOS 차속·기어·주차브레이크 상태, NaviHelper 서비스 연결을 확인했습니다. 이 신호를 연결한 탑승 브리핑·주행 상태·도착 확인·상세 리포트 MVP도 AVD에서 검증했습니다. ADAS SDK는 문서와 AVD 서비스는 확인했으나 공개 Maven 아티팩트가 확인되지 않아 배포 좌표·권한을 운영사에 확인한 뒤 LaneChange/Planning 이벤트에 연결합니다.

센서 계층은 `지원됨`, `권한 필요`, `신뢰도 부족`, `미지원` 상태를 공통 형식으로 반환합니다. 점수 엔진은 신뢰 가능한 사건만 평가하고 나머지는 사유와 함께 미평가 처리합니다. 현재 MVP에는 출발 25%·주행 50%·도착 25%의 설명 가능한 계산 규칙을 구현했으며, 제한속도 표본이 없는 경우 임의의 전체 점수를 만들지 않고 미평가 사유를 표시합니다. 안전벨트는 검증된 Vehicle Seat API로 구현합니다. 차선 변경·ADAS 기능은 SDK 확보 후 실제 API와 권한을 검증하며, 지원되지 않는 환경에서도 앱이 중단되거나 잘못 감점하지 않도록 capability 기반으로 동작합니다.

개발 순서는 다음과 같습니다.

1. Vehicle SDK/AAOS/NaviHelper/ADAS의 초기화, 권한, 이벤트 수신을 각각 작은 진단 화면에서 검증합니다. 현재 Vehicle SDK 주요 신호, AAOS 상태 조회와 NaviHelper 서비스 연결까지 완료했습니다.
2. 이벤트를 타임스탬프와 신뢰도와 함께 저장하는 로컬 데이터 계층과 평가 제외 규칙을 구현합니다.
3. 탑승 브리핑·Safe Drive·Safe Close·상세 리포트 화면을 구현합니다. 현재 전체 화면 흐름과 실신호 연결 MVP까지 완료했습니다.
4. CarUxRestrictions에 따라 주행 중 UI를 축소하고 상세 리포트는 정차·도착 후에만 제공합니다.
5. Pleos Connect Emulator와 Virtual Console에서 정상, 미지원, 권한 거부, 이벤트 지연 시나리오를 테스트합니다.
6. 핵심 흐름을 APK·GitHub 저장소·화면 녹화로 정리하고 실제 차량 환경에서 지원 차종별 capability를 추가 검증합니다.

1차 접수 전에는 핵심 API 검증 결과, 주요 화면, 동작 프로토타입을 제출하고, 2차 PT 전까지 출발 전–주행–도착 후의 한 사이클과 설명 가능한 리포트를 완성합니다.

## 6. 기대효과 및 발전 가능성

사용자는 결과 숫자를 보는 데서 끝나지 않고 다음 출퇴근에서 실천할 행동을 알 수 있습니다. 출발 전과 도착 후까지 포함해 반복적인 누락을 줄이고, ADAS·측정 불가 구간을 구분함으로써 운전점수에 대한 신뢰를 높일 수 있습니다.

초기 핵심 지표는 탑승 브리핑 확인율, 출발·도착 루틴 완료율, 평가 가능한 구간의 제한속도 준수율과 방향지시등 선행 사용률, 운전 종료 후 상세 리포트 열람률, 선택 행동의 최근 주행 대비 개선율, 4주차 유지율입니다. 사용자 인터뷰와 초기 파일럿 전에는 효과를 확정 수치로 주장하지 않고 목표값을 설정해 측정합니다.

초기 6개월 운영 목표는 검증 참여자와 공모전·App Market 유입을 합쳐 월간 활성 사용자 1,000명, 4주차 유지율 30%입니다. 이는 실적이 아닌 제품 목표이며, `접근 가능한 대상 사용자 × 설치율 × 월간 활성률`로 실제 공개 시장 자료와 파일럿 결과가 확보되는 즉시 보정합니다. 출퇴근 때마다 제공되는 짧은 탑승 브리핑과 필요할 때 열어 보는 상세 리포트를 유지율의 핵심 구조로 사용합니다.

서비스는 개인 출퇴근 운전자에서 시작해 초보 운전자와 가족 안전 코칭, 법인·플릿 운전자 교육, 정비·보험·안전 캠페인 제휴로 확장합니다. 장기적으로는 차종·센서별 capability 맵과 익명화된 습관 개선 지표를 축적해 차량별로 공정한 코칭을 제공하고, 운전자 동의가 있는 경우에만 제휴 혜택과 연결합니다.
