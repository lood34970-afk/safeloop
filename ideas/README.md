# 아이디어 포트폴리오

공모전 아이디어를 서로 섞지 않고 같은 기준으로 비교·발전시키기 위한 작업 공간이다. 현재 루트의 Android 앱과 `docs/`는 이미 구현이 진행된 SafeLoop 산출물이므로 이동하지 않고, 이 폴더에서 아이디어별 인덱스만 관리한다.

## 아이디어 현황

| 번호 | 아이디어 | 단계 | 한 줄 설명 | 기획서 |
|---:|---|---|---|---|
| 01 | SafeLoop | 프로토타입 검증 | 차량 데이터로 출발·주행·도착 안전 습관을 설명하는 운전 코치 | [기존 산출물 안내](01-safeloop/README.md) |
| 02 | Drive Canvas | 프로토타입 검증 | 도로망을 분석해 그림 모양의 안전한 주행 경로를 만들고 완주 결과를 콘텐츠로 남기는 GPS 아트 드라이브 | [기획서](02-drive-canvas/docs/02_proposal.md) |

## 폴더 규칙

새 아이디어는 `_template`을 복사해 `NN-kebab-case-name`으로 만든다.

```text
ideas/
├─ README.md                 # 전체 후보 현황과 비교 인덱스
├─ _template/                # 새 아이디어 복사용 기본 구조
├─ 01-safeloop/
└─ 02-drive-canvas/
   ├─ README.md              # 상태, 한 줄 요약, 핵심 링크
   ├─ docs/
   │  ├─ 01_concept.md       # 한 장 아이디어 캔버스
   │  ├─ 02_proposal.md      # 상세 기획서
   │  └─ 03_validation.md    # 가설·기술·사용자 검증 계획
   ├─ research/              # 인터뷰, 경쟁 서비스, 기술 조사
   ├─ assets/                # 이미지, 화면 시안, 다이어그램
   └─ prototype/             # 아이디어 전용 코드·실험과 실행 안내
```

## 단계 정의

1. `아이디어`: 한 줄 제안만 정리한 상태
2. `기획 초안`: 문제·사용자 흐름·MVP·리스크를 문서화한 상태
3. `검증 중`: 사용자 또는 SDK/API 가설을 실제로 확인하는 상태
4. `프로토타입 검증`: 핵심 경험을 실행 가능한 산출물로 증명한 상태
5. `제출 후보`: 공식 제안서로 발전시키기로 결정한 상태
6. `보류`: 근거를 남기되 현재 작업 우선순위에서는 제외한 상태

## 운영 원칙

- 모든 아이디어는 공통 평가 기준인 차량특화성·창의성·기술 활용성·사업성으로 비교한다.
- 확인하지 않은 SDK 기능과 효과 수치는 `가설`로 표시한다.
- 공용 자료는 기존 `docs/`에 두고, 특정 아이디어에만 필요한 자료는 해당 아이디어 폴더에 둔다.
- 앱 구현을 시작하기 전 `docs/03_validation.md`에서 가장 큰 실패 가설부터 정한다.
- 최종 제출 후보가 정해지기 전에는 아이디어별 프로토타입을 서로 의존시키지 않는다.
